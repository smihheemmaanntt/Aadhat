# Aadhat Hybrid Easy Process

This guide keeps one rule first: the current single-user app remains unchanged until hybrid mode is explicitly enabled.

## 1. Normal Single User

No setup is required.

- If `hybrid.json` does not exist, or if `"Enabled": false`, the app continues to use the existing local SQLite `Data.db`.
- Existing users should not see any change.
- Do not enable hybrid mode for a company until the server and access setup are complete.

## 2. Server Installation

On the server PC, office PC, VPS, or hosting account:

1. Install XAMPP/PHP and MySQL/MariaDB.
2. Copy the `aadhat-api` folder to the server.
3. Create one MySQL database, for example `aadhat_hybrid`.
4. Generate config:

```text
aadhat-api\tools\setup-config.cmd 127.0.0.1 aadhat_hybrid root ""
```

5. Save the printed API token. The desktop app uses the same value as `ApiToken`.
6. Install the schema:

```text
aadhat-api\tools\aadhat-admin.cmd install-schema
```

7. Check the API in a browser:

```text
http://server-ip/aadhat-api/public/api/health
```

For same-PC local testing with the PHP development server:

```text
http://127.0.0.1:8088/api/health
```

Open the admin UI:

```text
http://127.0.0.1:8088/admin
```

Log in with the API token printed by `setup-config.cmd`.

## 3. Company Registration

One server database can contain many companies. Access is controlled separately for each customer and company.

Example:

```text
aadhat-api\tools\aadhat-admin.cmd register-company 1 "Demo Company" LocalOnly
```

Company modes:

- `LocalOnly`: the company is active in local SQLite.
- `OnlineOnly`: the company is active on server SQL through the API.
- `SyncingToOnline`: local-to-web transfer is running; writes must stay locked.
- `SyncingToLocal`: web-to-local transfer is running; writes must stay locked.
- `ReadOnlyArchive`: old data is available only for reports or backup.

## 4. Developer Authorization Key

Only the app owner/developer should create multiuser permission. The customer/operator should not receive direct database access, MySQL password, or the server API token separately.

The easiest method is through the web admin:

1. Open `/admin`.
2. Register the company if it is not already registered.
3. In `Authorization Key`, enter customer code, company code, allowed PC count, and API URL.
4. Click `Generate Setup Code`.
5. Copy the `Desktop Setup Code`.

This one setup code contains the API URL, API token, authorization key, customer code, and company code. The desktop app can import it and activate the PC automatically.

Command-line generation is still available for developer use.

Example: allow customer `CUST001` to use 3 PCs:

```text
aadhat-api\tools\generate-key.cmd CUST001 3 "Customer office"
```

The tool prints a key like this:

```text
ADH-XXXXXX-XXXXXX-XXXXXX
```

Give this key to the customer once. The server stores only the key hash, not the plain key.

## 5. Grant Company Access

If the company code is entered while generating the setup code, access is granted automatically. You only need this separate step when granting or changing access manually.

Allow a customer to open a specific company:

```text
aadhat-api\tools\aadhat-admin.cmd grant-company CUST001 1
```

Remove access:

```text
aadhat-api\tools\aadhat-admin.cmd revoke-company CUST001 1
```

View companies and access:

```text
aadhat-api\tools\aadhat-admin.cmd list-companies
```

## 6. Client PC Activation

On each client PC, log in as an Admin user, open the desktop app, and go to:

```text
Tools > Hybrid Settings
```

Operator users cannot see this menu. This keeps multiuser permission under app owner/admin control.

Simple method:

1. Paste the `Desktop Setup Code` from the web admin into `Setup Code`.
2. Click `Import + Activate`.
3. The app fills API URL, API token, authorization key, activates the PC, saves the device token, enables hybrid mode, and writes `hybrid.json`.

Manual fields remain available for developer troubleshooting.

Enter:

- `API URL`: server URL, for example `http://192.168.1.10/aadhat-api/public`
- `API Token`: token printed by `setup-config.cmd`
- `Authorization Key`: customer key generated by the developer
- `Enable Hybrid Mode`: tick this only after the API test and activation are ready

Click `Test API` first. If it succeeds, click `Activate PC`. The server returns a device token and the screen saves it automatically.

Manual example for reference:

Example:

```json
{
  "Enabled": true,
  "ApiBaseUrl": "http://server-ip/aadhat-api/public",
  "ApiToken": "server-api-token",
  "AuthorizationKey": "ADH-XXXXXX-XXXXXX-XXXXXX",
  "DeviceToken": "",
  "LastCompanyCode": ""
}
```

Activation endpoint:

```text
POST /api/device/activate
```

After activation, the server returns `device_token`. The desktop screen saves that value in `hybrid.json` as `DeviceToken`.

If the allowed PC limit is already full, the next PC will not activate. The developer can block, release, or review activated PCs from the admin UI.

The `Disable Hybrid` button unticks hybrid mode and saves `"Enabled": false`, so the desktop app returns to local SQLite mode.

View activated devices:

```text
aadhat-api\tools\aadhat-admin.cmd list-devices CUST001
```

Block a device:

```text
aadhat-api\tools\aadhat-admin.cmd block-device DEVICE_ROW_ID
```

Release a device:

```text
aadhat-api\tools\aadhat-admin.cmd release-device DEVICE_ROW_ID
```

## 7. Local to Web

Use this when a company should move from local SQLite to the online SQL server.

Process:

1. Set company mode:

```text
aadhat-api\tools\aadhat-admin.cmd set-mode 1 SyncingToOnline
```

2. Lock local writes and take a backup.
3. Upload local SQLite data to the online server tables.
4. Verify vouchers, ledgers, stock, receipts, payments, and balances.
5. Set company mode:

```text
aadhat-api\tools\aadhat-admin.cmd set-mode 1 OnlineOnly
```

6. All active clients now work through the online API/SQL database.

Create a transfer job record:

```text
aadhat-api\tools\aadhat-admin.cmd request-transfer 1 LocalToOnline Developer
```

## 8. Web to Local

Use this when an online company should return to a single local PC.

Process:

1. Set company mode:

```text
aadhat-api\tools\aadhat-admin.cmd set-mode 1 SyncingToLocal
```

2. Lock online writes for that company.
3. Export/download final server data into SQLite `Data.db`.
4. Verify data on the local PC.
5. Set company mode:

```text
aadhat-api\tools\aadhat-admin.cmd set-mode 1 LocalOnly
```

6. Disable or delete `hybrid.json`, or set `"Enabled": false`.
7. The desktop app starts using local SQLite again.

Create a transfer job record:

```text
aadhat-api\tools\aadhat-admin.cmd request-transfer 1 OnlineToLocal Developer
```

## 9. Multiuser to Single

If a customer wants to stop multiuser and use one PC only:

1. Make sure all users log out.
2. Set mode:

```text
aadhat-api\tools\aadhat-admin.cmd set-mode 1 SyncingToLocal
```

3. Export final online data to local SQLite.
4. Verify the local data.
5. Set mode:

```text
aadhat-api\tools\aadhat-admin.cmd set-mode 1 LocalOnly
```

6. On the client PC, disable hybrid:

```json
"Enabled": false
```

## 10. Single to Multiuser

If a customer later wants multiuser again:

1. Take a local backup.
2. Register the company on the server if it does not already exist.
3. Grant customer access to the company.
4. Generate or confirm the authorization key and PC limit.
5. Set mode:

```text
aadhat-api\tools\aadhat-admin.cmd set-mode 1 SyncingToOnline
```

6. Upload and verify local data on the online server.
7. Set mode:

```text
aadhat-api\tools\aadhat-admin.cmd set-mode 1 OnlineOnly
```

8. Activate client PCs.

## 11. Safety Checklist

- Only one master should accept writes for one company at one time.
- When local mode is active, online writes must stay locked.
- When online mode is active, local writes must stay locked.
- During transfer, all writes must stay locked.
- Every API request must validate customer, device, and company access.
- Client PCs must never receive the direct database password.
- Do not commit `config.php` or `hybrid.json` to source control.
